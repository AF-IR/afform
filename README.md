# آرشام فرم (Arsham Form)

**سامانه هوشمند طراحی پرسشنامه، آزمون و فرم آنلاین**
«فرم بساز، آزمون برگزار کن، پاسخ‌ها را تحلیل کن.»

آرشام فرم یک محصول SaaS واقعی و تمام‌فارسی (RTL) است: کاربران بدون کدنویسی فرم می‌سازند، لینک عمومی امن می‌گیرند، پاسخ‌ها را با کنترل کامل سمت سرور دریافت و تحلیل می‌کنند.

---

## ⚡ اجرای سریع (حالت پیش‌نمایش محلی)

بدون هیچ تنظیمی، پروژه با **حالت پیش‌نمایش محلی** اجرا می‌شود (Auth واقعی با رمز هش‌شده + SQLite):

```bash
bun install
cp .env.example .env.local        # LOCAL_AUTH_SECRET را با `openssl rand -base64 32` پر کنید
bun run db:push                   # ساخت جداول SQLite
bun run dev                       # http://localhost:3000
```

در این حالت همه قابلیت‌ها واقعی کار می‌کنند (ثبت‌نام، ساخت فرم، انتشار، ثبت پاسخ، نمره‌دهی، خروجی‌ها) اما داده‌ها روی SQLite همین سرور ذخیره می‌شوند و «ارسال ایمیل» وجود ندارد (لینک بازیابی رمز در همان صفحه نمایش داده می‌شود). این وضعیت در رابط کاربری پروفایل با نشان «حالت پیش‌نمایش محلی» شفاف اعلام می‌شود.

> وضعیت فعلی sandbox همین حالت است: متغیرهای Supabase تنظیم نشده‌اند و هیچ کلیدی جعل نشده است.

## 🚀 استقرار واقعی (Supabase + Vercel)

### گام ۱ — ساخت پروژه Supabase
1. در [supabase.com](https://supabase.com) یک پروژه رایگان بسازید.
2. از **Project Settings → API** سه مقدار را بردارید: `Project URL`، `anon public key` و `service_role key`.

### گام ۲ — اجرای مایگریشن‌ها
- مسیر **SQL Editor** را باز کنید و محتوای `supabase/migrations/0001_init.sql` را کامل اجرا کنید.
- سپس `supabase/migrations/0002_ai_analyses.sql` را اجرا کنید (جدول «تحلیل هوش مصنوعی نتایج» + RLS مالک‌محور + ایندکس).
- این اسکریپت‌ها: جداول (`profiles`, `forms`, `questions`, `responses`, `answers`, `uploaded_files`, `ai_analyses`)، ایندکس‌ها، تریگر `updated_at`، تریگر ساخت خودکار پروفایل هنگام ثبت‌نام، **همه سیاست‌های RLS** و باکت خصوصی `form-uploads` را می‌سازند.

### گام ۳ — تنظیم Authentication در Supabase
- **URL Configuration → Site URL**: `https://aflab.vercel.app` (یا دامنه سفارشی شما)
- **Redirect URLs** این‌ها را اضافه کنید:
  - `https://aflab.vercel.app/auth/callback`  (تأیید ایمیل و بازیابی رمز)
  - `http://localhost:3000/auth/callback` (توسعه محلی)
- اگر می‌خواهید ثبت‌نام با تأیید ایمیل انجام شود، گزینه **Confirm email** را در بخش Email فعال نگه دارید (پلن رایگان Supabase سقف ارسال ایمیل دارد و برای ارسال انبوه باید SMTP اختصاصی تنظیم شود).

### گام ۴ — متغیرهای محیطی در Vercel
| متغیر | مقدار | سمت |
|---|---|---|
| `NEXT_PUBLIC_SITE_URL` | `https://aflab.vercel.app` | public |
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL | public |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon key | public (کلید عمومی) |
| `SUPABASE_SERVICE_ROLE_KEY` | service_role key | **فقط سرور** — هرگز به کلاینت ندهید |
| `ZAI_API_KEYS` | چند کلید API رایگان Z.AI، با کاما جدا شده | **فقط سرور** — برای «تحلیل هوش مصنوعی نتایج» |
| `ZAI_MODEL` | `glm-4.5-flash` (پیش‌فرض) | اختیاری |
| `ZAI_BASE_URL` | `https://api.z.ai/api/paas/v4` (پیش‌فرض) | اختیاری |
| `NEXT_PUBLIC_SUPPORT_EMAIL` | ایمیل پشتیبانی (در فوتر/درباره ما/مگامنو نمایش داده می‌شود) | public — اختیاری |
| `NEXT_PUBLIC_CONTACT_PHONE` | شماره تماس | public — اختیاری |
| `NEXT_PUBLIC_TELEGRAM` / `NEXT_PUBLIC_WHATSAPP` | آیدی تلگرام بدون @ / شماره واتس‌اپ بدون + | public — اختیاری |
| `NEXT_PUBLIC_INSTAGRAM` / `NEXT_PUBLIC_X_TWITTER` | آیدی شبکه اجتماعی بدون @ | public — اختیاری |
| `NEXT_PUBLIC_SUPPORT_HOURS` | ساعات پاسخ‌گویی به‌صورت یک جمله | public — اختیاری |

> هر کانال تماسی که خالی بماند در رابط کاربری نمایش داده نمی‌شود — هیچ داده جعلی در سایت وجود ندارد. فهرست کامل متغیرها با توضیح فارسی در `.env.example` آمده است.

### تحلیل هوش مصنوعی نتایج (Z.AI)
در صفحه «گزارش و تحلیل» هر فرم، کارت «تحلیل هوش مصنوعی نتایج» به‌صورت خودکار آمار واقعی فرم (توزیع گزینه‌ها، میانگین امتیازها، روند ۳۰ روزه، نرخ قبولی آزمون و نمونه پاسخ‌های متنی) را به مدل GLM می‌دهد و خروجی ساختاریافتهٔ فارسی دریافت می‌کند: خلاصهٔ تحلیلی، یافته‌های کلیدی، نکات قابل توجه و پیشنهادهای بهبود. هر تحلیل در جدول `ai_analyses` ذخیره می‌شود و با کلیک «تحلیل مجدد» نسخهٔ تازه ساخته می‌شود.

**مدیریت کلیدها (ZAI_API_KEYS):**
- چند کلید رایگان از [z.ai/manage-apikey](https://z.ai/manage-apikey/apikey-list) بسازید و با کاما در یک متغیر وارد کنید:
  `ZAI_API_KEYS="key-one,key-two,key-three"`
- در هر درخواست، **به‌صورت تصادفی** از کلیدها استفاده می‌شود؛ اگر کلیدی خطا داد (401/429/5xx/قطع شبکه/پاسخ خالی) به‌صورت خودکار **کلید بعدی** امتحان می‌شود تا یکی موفق شود.
- کلیدها فقط سمت سرور مصرف می‌شوند، در لاگ‌ها فقط با اثر انگشت ماسک‌شده ظاهر می‌شوند و هرگز به کلاینت ارسال نمی‌شوند.
- محدودیت نرخ: هر کاربر حداکثر ۸ تحلیل در ۱۰ دقیقه (محدیت درون‌حافظه‌ای؛ مستند در بخش محدودیت‌ها).
- اگر `ZAI_API_KEYS` تنظیم نشده باشد، خطای 503 با راهنمای فارسی برمی‌گردد (در حالت پیش‌نمایش محلی، SDK پلتفرم به‌عنوان جایگزین استفاده می‌شود).

### گام ۵ — اتصال به Vercel
1. ریپو را به Vercel وصل کنید (فریم‌ورک Next.js به‌صورت خودکار شناسایی می‌شود).
2. متغیرهای بالا را در Project Settings ثبت کنید.
3. Deploy بزنید. Build دستور `next build` است و خروجی `standalone` تولید می‌شود.

### گام ۶ — تست‌های پس از استقرار
- [ ] ثبت‌نام → تأیید ایمیل (در صورت فعال‌بودن) → ورود
- [ ] ساخت فرم از قالب → افزودن سؤال → انتشار
- [ ] باز کردن لینک عمومی در مرورگر ناشناس → ثبت پاسخ
- [ ] مشاهده پاسخ‌ها، گزارش‌ها و خروجی CSV/Excel/JSON
- [ ] بررسی RLS: با حساب دوم تلاش کنید به `/api/forms/{id فرم دیگری}` دسترسی یابید → باید `404` بگیرید
- [ ] آزمون زمان‌دار: پس از اتمام زمان، ارسال پاسخ باید با پیام «زمان به پایان رسیده» رد شود

## 🏗 معماری

```
src/
  app/                      صفحات (App Router) + Route Handlers
    api/auth/…              ثبت‌نام، ورود، بازیابی رمز، پروفایل
    api/forms/…             CRUD فرم/سؤال، پاسخ‌ها، گزارش، خروجی
    api/public/forms/…      خط عمومی: خواندن فرم، شروع آزمون، ثبت پاسخ، آپلود
    dashboard/…             داشبورد مالک (همه مسیرها محافظت‌شده)
    f/[publicId]/           فرم عمومی
  components/               UI (shadcn/ui) + بیلدر + رندر سؤال + نمودارها
  lib/
    forms/backend-local.ts     بک‌اند SQLite (پیش‌نمایش)
    forms/backend-supabase.ts  بک‌اند Supabase (تولیدی؛ عملیات مالک با کلاینت کاربر → RLS واقعاً اعمال می‌شود)
    forms/service.ts           خط لوله مشترک: پنجره زمانی، سقف پاسخ، تلاش، تایمر، منطق شرطی، نمره‌دهی
    validation/schemas.ts      اعتبارسنجی zod مشترک کلاینت/سرور
    scoring/grade.ts           نمره‌دهی خودکار
    exports/exporters.ts       CSV/XLSX/JSON با ضد CSV-Injection
supabase/migrations/0001_init.sql   اسکیمای کامل + RLS + ایندکس + باکت
```

**نکته امنیتی:** عملیات مالک (فرم/پاسخ/گزارش) با کلاینت کاربر-محدود Supabase انجام می‌شود تا RLS واقعاً اجرا شود؛ خط عمومی فرم‌ها (خواندن/شروع/ثبت) سمت سرور با service role اجرا می‌شود و این کلید هرگز در بسته‌های کلاینت قرار نمی‌گیرد.

## 📊 مدل داده
`profiles` ← `forms` (شناسه عمومی غیرترتیبی) → `questions` (تنظیمات/امتیاز/قواعد شرطی در JSONB ساختاریافته و اعتبارسنجی‌شده) → `responses` (نمره، تلاش، کلید ناشناس هش‌شده) → `answers`.

## 🧪 تست‌های دستی پیشنهادی
سناریوهای §۲۳ مستندات محصول (auth، فرم، پاسخ، آزمون، امنیت) همه از مسیر رابط کاربری یا curl قابل اجراست؛ منطق حیاتی (اعتبارسنجی پاسخ، نمره‌دهی، منطق شرطی) توابع خالص و قابل تست واحد هستند (`src/lib/scoring`, `src/lib/forms/conditional`, `src/lib/validation`).

## ⚠️ محدودیت‌های پلن رایگان (مستند و صادقانه)

| سرویس | محدودیت کلیدی پلن رایگان |
|---|---|
| Vercel | اجرای Serverless با سقف اجرا و پهنای باند ماهانه؛ محدودیت حجم بدنه درخواست (~۴.۵MB → آپلود فایل حداکثر ۴MB) |
| Supabase | حجم دیتابیس ۵۰۰MB، پهنای باند و سقف کاربران ماهانه Active؛ سقف ارسال ایمیل احراز هویت (برای ارسال انبوه، SMTP اختصاصی لازم است) |
| Rate Limiting | نسخه فعلی in-memory است و در محیط Serverless فقط یک نمونه گرم را محافظت می‌کند؛ برای محدودسازی توزیع‌شده، Upstash Redis (پلن رایگان محدود) یا مشابه آن را اضافه کنید — نقطه اتصال در `src/lib/rate-limit.ts` آماده است |
| CAPTCHA | پیاده‌سازی نشده؛ در صورت نیاز، Wire-up برای Cloudflare Turnstile در مسیر `submit` پیش‌بینی شده و باید با اعتبارسنجی سمت سرور فعال شود |

## 📌 وضعیت قابلیت‌ها (شفاف)

**پیاده‌سازی‌شده و فعال:** ثبت‌نام/ورود/بازیابی رمز (دو-بکی)، سازنده فرم با ۲۲ نوع سؤال + گزینه «سایر»، منطق شرطی ساختاریافته، انتشار با پنجره زمانی/سقف/ناشناس/ایندکس، آزمون با نمره‌دهی خودکار و تایمر سمت سرور و سقف تلاش، پاسخ‌ها با جست‌وجو/فیلتر/صفحه‌بندی، گزارش‌های نموداری، خروجی CSV/Excel/JSON، آپلود فایل امن، RLS کامل، RTL فارسی کامل، SEO (metadata، sitemap، robots، FAQ Schema).

**عمداً خارج از محدوده فعلی (نمایشی هم نیست):** پرداخت/اشتراک، همکاری چندنفره (جدول `form_collaborators` در طرح آمده ولی فعال نیست)، نمره‌دهی دستی تشریحی، ویرایش پاسخ از مرورگر دیگر، اعلان ایمیل دریافت پاسخ.

## 🔎 سئو و آدرس‌ها (Indexable URLs)
- همه لینک‌های ناوبری (هدر، مگا‌منو، فوتر) به «مسیر واقعی» اشاره می‌کنند — هیچ آدرس هش‌دار (`/#…` یا `#/route`) در ناوبری استفاده نشده تا همه صفحات به‌راحتی ایندکس شوند.
- صفحات عمومی و ایندکس‌شدنی: `/`، `/features`، `/templates`، `/plans`، `/faq`، `/about`، `/terms`، `/privacy-policy`، `/register`، `/login` (در `sitemap.xml`).
- صفحات خصوصی که در `robots.txt` مسدود شده‌اند: `/dashboard`، `/api`، `/f/`، `/auth`، `/forgot-password`، `/reset-password`.
